## 一、阶段 1：安全与可靠性 P1（阻塞合并，4-6h）

### 1.1 [G-P1-2] `httpClient(caPath)` CA 加载失败改硬错误（1h）

- 影响：nuclei_upgrade + nuclei_templates_update + agent_upgrade 三条下载链路都受影响。
- 测试：`TestHTTPClientCAFailHard`（传入不存在文件路径，断言返回 error）。

### 1.2 [S-P1-2 + G-P1-5] Nuclei 下载加固：大小限制 + 超时（1h）

- Go `HandleNucleiUpgrade` (`upgrade.go:223`)：HTTP client timeout 从默认 60s → 120s（同 `HandleNucleiTemplatesUpdate` 的 5min 超时模式）
- 测试：`TestNucleiUpgradeRejectsOversizedZip` + `TestNucleiUpgradeTimeout`

### 1.3 [S-P1-6] `nuclei_download_base_url` 默认值改空串（0.5h）

## 五、阶段 5：继承自更早版本的开放问题

### 5.1 SSE 路由顺序 bug（V9 遗留）

`GET /api/v1/events/stream` 被 `GET /api/v1/events/{event_id}/stream` 遮蔽，FastAPI 按注册顺序匹配。`{event_id}` 抢走 "stream" 字符串作为 event_id。
- 修复：调整 `stream.py` 中两条路由的注册顺序（具体路径 `/events/stream` 放在参数路径 `/{event_id}/stream` 之前）
- 测试：`test_events_stream_not_masked_by_event_id_stream`

### 5.2 `install.sh` token 安全（Go P2 遗留）

当前 install.sh 把 enroll token 嵌入 URL query params（可见于代理日志/进程列表/shell 历史）。理想方案是改为 `Authorization: Bearer` header，但需要 Go agent 下载逻辑配合。
- 短期：install.sh 中 curl 加 `-H "Authorization: Bearer $TOKEN"`，Go `HandleDownload` 从 header 读 token
- 长期：考虑 token 用过即焚（一次性使用）

### 5.3 VulnFilter ES wildcard 查询性能（V10 遗留）

`store.py` 中 keyword 查询使用 `wildcard` + `re.escape`，在 ES 大量数据下性能不佳。
- 修法：ES mapping 显式声明 `.keyword` 子字段，查询走 `term` / `match_phrase_prefix` 而非 `wildcard`
- 属于 ES 索引优化，风险低但收益大（随数据增长）
