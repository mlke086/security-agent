## 零、实施原则

- 一次提交一个 P1（或一组强相关 P2），配独立测试；提交前跑「P0 切片」（取消链路 + 升级链路 + ES trace + web search）确认无回归。
- 不在没有测试保护的地方改历史 P0 链路。
- 每修一项更新 `docs/项目审查V12.md` 对应条目状态（FIXED / 部分 / 回归），保留 commit 与文档对应。
- Go 修改配 `go vet` + 对应 `*_test.go` 用例；前端修改配 `npx tsc --noEmit` 类型检查。
- **已有回归测试锁定的行为（如 `TestIsTaskCancelledFailClosed` 锁 fail-closed）不能直接推翻，修法必须兼容既有测试**。

### 1.1 [S-P1-9] `_is_task_cancelled` 误杀健康任务——二次确认 + audit（1.5h）—— 最优先

- `src/orchestration/subgraphs/vulnscan/nodes.py:1004-1044`：redis/Nacos 查询异常时 `return True`（fail-closed），collect 每 5 秒轮询（:466）→ 30 分钟窗口内任何 redis 抖动都会把健康任务标记 cancelled 并终止子图，agent 端结果变孤儿数据。
- **约束**：`tests/unit/orchestration/test_vulnscan_nodes.py:1115-1143` 的 `TestIsTaskCancelledFailClosed` 三个测试锁定"redis 错误 → 返回 True"，**不得简单 fail-open**。
- 修法（兼容既有测试，二选一）：
  - **A（推荐）**：`_is_task_cancelled` 保持 fail-closed；调用方 collect:466 在 `store.update_task(status="cancelled")` 前**间隔 1s 二次确认**（`_is_task_cancelled` 再调一次），两次都判取消才落 cancelled；仅一次时写 audit `cancellation_check_degraded` + task reason 标注 "unconfirmed"。
  - **B**：collect 轮询间隔 5s → 15s，缩小误杀窗口 + 落 cancelled 前写 degraded 标记。
- 测试：新增 `test_collect_second_confirmation_before_cancel`（第一次 True 第二次 False → 不标 cancelled）+ 现有 `TestIsTaskCancelledFailClosed` 必须保持通过。
