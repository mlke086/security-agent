## 六、风险与注意（在方案 §6 基础上的增量）

1. **D1 TaskWorker 参数化**是需求②最大的隐性前置依赖，务必在阶段 A 先行并回归 vulnscan 队列测试。
2. **后端 versionCompare 新写**（D3）：移植 Go 逻辑时注意 CPE 版本格式差异（`_`/`-`/epoch），单测覆盖边界（1.18.0 vs 1.18、1.18.0-rc1 等）。
3. **ES 体量**：57.6 万点/天（100 主机×15s），30d 清扫任务必须随 S5 一并上线；dev 环境可用更长 interval 降噪。
4. **旧 Agent 兼容**：服务端无 host_metrics 分支天然兼容；前端空数据显示"未上报"引导文案。
5. **nmap/masscan 需本机安装**才能做扫描引擎本地调试；Windows 开发机上可用 WSL/Linux 容器跑资产扫描联调。
6. **需求②网络冲击**：默认 `masscan_rate=2000`、大网段分块、爆破默认关——上线前按目标网络评估限速值。
