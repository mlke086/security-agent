# SecAgent 项目功能梳理与架构图

> 生成日期：2026-07-26
> 依据：代码知识图谱 + 项目审查V8 + 功能演示讲解 + 设计文档 + 源码复核

---

## 一、项目定位

**SecAgent** 是一套基于大模型（LLM）的安全事件智能分析与自动响应平台，以 **「告警研判 + 漏洞扫描 + 响应处置 + AI 对话」** 四大能力构成安全运营闭环。

- **技术栈核心**：LangGraph 编排引擎 + FastAPI + React 18 + Go Agent + 7 个中间件
- **当前版本**：0.1.0
- **质量状况**：ruff + mypy ✅ | 257+ 单测 | P0 阻塞项 = 0

## 二、已完成功能全景

### 1. 安全告警智能研判

| 功能 | 说明 |
|------|------|
| 告警接入 | Kafka（aiokafka）+ HTTP POST 双入口，带脱敏预处理 |
| 智能分流 | 入口 orchestrator：蜜罐规则优先命中 + LLM 分类兜底 |
| 多步推理链 | entry → 分流 → CTI分析 → 综合研判 → 汇聚 → 结论，每步带耗时/输入输出摘要 |
| IOC 提取+脱敏 | 自动提取 IP/域名/Hash/URL，7 条脱敏规则热加载 |
| 置信度评分 | VerdictResult（verdict + confidence + evidence + mitre_ttps） |
| GraphRAG 知识增强 | Milvus 向量检索 + Neo4j ATT&CK 图谱（2143节点）+ BGE-large-zh-v1.5 嵌入（1024维） |
| 威胁情报 | VirusTotal 并行查询 + AlienVault OTX + RRF 融合 |
| PoC 验证 | vuln_hunter 子图：LLM生成PoC → AST安全审查 → Docker沙箱隔离执行（≤10轮循环） |
| 推理链持久化 | ES 存储完整 trace，按 event_id 聚合查询 |
| 实时推送 | SSE 通道：事件流/单事件推理/指标流 |

### 2. 漏洞主动扫描

| 功能 | 说明 |
|------|------|
| 表单式任务创建 | 目标选择器（按主机组/主机名/IP-CIDR）、扫描模块（sys_vuln/baseline）、引擎选择（matcher/Nuclei） |
| 对话式任务创建 | AI 对话界面，自然语言描述 → LLM解析意图 → 结构化 ScanIntent → 确认卡片 → 执行 |
| 多引擎扫描 | `matcher`（Agent 端规则引擎 CVE 精确匹配）+ `nuclei`（Nuclei CLI YAML 模板） |
| 实时进度监控 | SSE 事件流：scan_start / host_done / finding / task_done，进度条实时更新 |
| 扫描取消 | 状态机 + Redis 墓碑 + Agent context 传递，中途取消 |
| 定时调度 | 支持 cron 表达式定时执行 |
| AI 漏洞评估 | LLM 二次过滤/定级，降低误报率 |
| 漏洞清单管理 | 全量列表 + 筛选（等级/状态）+ 批量标记（已修复/已接受）+ AI 误报标记 |
| 扫描报告 | 统计摘要 + 主机汇总 + 详细发现 + 修复建议 + HTML 导出 |
| 规则管理 | CVE 规则列表 + 中文化 + 筛选搜索 + 详情查看 + 离线 ZIP 导入 + 签名分发到 Agent |
| 规则同步 | NVD 抓取 → 规则转换 → ES/PG 持久化 → Ed25519 签名 → WS 下发 → Agent 热加载 |

### 3. 自动响应处置

| 功能 | 说明 |
|------|------|
| 预设剧本 | 10 个 YAML playbook（爆破 / CVE漏洞利用 / 数据泄露 / DDoS / DNS隧道 / 横向移动 / 恶意软件 / 钓鱼 / 勒索 / 未授权访问） |
| 剧本匹配 | trigger 规则优先（verdict + confidence_min + event_tags），未命中则 LLM 动态生成 |
| HITL 分级审批 | L1/L2 自动批准；L3 需 1 人审批；L4/L5 需 2 人 quorum |
| 原子 quorum | Redis Hash + Set + ZSet + Lua 脚本 |
| 审批通知 | 企微/钉钉 webhook 推送审批卡片 |
| 超时兜底 | Celery 定时任务（L3=300s / L4=900s / L5=1800s） |
| 动作执行 | ActionDispatcher：notify（通知）、siem_tag（SIEM打标）、dns_block（DNS拦截）、simulator（防火墙/隔离占位） |
| 安全闸 | 幂等派发 + dry_run 默认开启 + 回滚支持 |

### 4. 主机纳管（Agent）

| 功能 | 说明 |
|------|------|
| 注册入网 | Ed25519 密钥交换 → enroll token（TTL过期）→ 获取 agent_id + agent_token |
| WebSocket 长连接 | 心跳通信 + 任务指令接收 + 结果上报，支持跨 worker pub/sub 路由 |
| 主机分组 | 按业务线/机房/等级分组，含主机组 CRUD |
| Agent 生命周期 | 在线/离线检测 + 下线（decommission）+ 永久删除（含 token 吊销 + WS 断连） |
| 远程升级 | 服务端推送新版本 → Ed25519 签名校验 → 原子替换 + ack-then-restart |
| 规则热更新 | 签名校验 + 下载规则包 + 内存热加载，无需重启 |
| 资源监控 | CPU/内存/磁盘监控，扫描限流避让业务 |
| 离线消息队列 | SQLite 本地缓存，重连后自动续传 |
| 跨平台 | Linux (amd64/arm64) + Windows + macOS |

### 5. AI 对话助手

| 功能 | 说明 |
|------|------|
| 4 路意图路由 | scan（扫描意图解析）/ project（项目文档 RAG 问答）/ web（联网搜索 CVE/安全新闻）/ chat（自由对话） |
| 多轮对话 | 历史持久化 + 多会话管理（创建/切换/删除） |
| 模型切换 | 每轮可选择不同 LLM 模型 |
| 确认卡片 | 扫描意图解析后展示结构化确认卡片，防误操作 |

### 6. 平台基础能力

| 功能 | 说明 |
|------|------|
| 认证与权限 | JWT HS256 + RBAC 四角色（admin/analyst/responder/viewer） |
| 态势感知大屏 | 4 统计卡片 + 饼图 + 柱状图 + 趋势折线图，SSE 实时刷新 |
| 事件队列与详情 | 事件列表（筛选/分页）+ 详情页（推理链 Timeline + IOC 展示 + 审批状态） |
| 四套主题 | 亮色/暗色/亮侧栏+暗内容/暗侧栏+亮内容，一键切换 |
| 模型管理 | llm_models 表 + ModelAdapter 统一抽象层，支持 DeepSeek/Claude/OpenAI/vLLM，CRUD + 默认切换 + API Key 安全 |
| 审计日志 | ES 审计写入，所有操作全程可追溯 |
| 演示数据 | 一键注入 5 条样例事件（含 L3 待审批） |
| 代码质量 | ruff + mypy(strict) + pytest(257+) + Playwright E2E |

**关键节点说明**：

| 节点 | 读取状态 | 写入状态 |
|------|---------|---------|
| `entry` | raw_event.event_id | event_id, stage="triage", audit_log |
| `orchestrator` | raw_event | priority, event_tags, stage="route", audit_log |
| `route_decision` | priority, event_tags | → investigate / vuln_check / ignore |
| `investigate` | raw_event.iocs | subgraph_result={final_verdict, confidence_score, evidence_summary, mitre_ttps} |
| `vuln_check` | raw_event | stage="verify", subgraph_result={final_poc, is_vulnerable, exploit_chain} |
| `aggregator` | subgraph_result | final_verdict, confidence_score, stage="done", audit_log |
| `route_after_verdict` | subgraph_result, stage | → respond / vuln_check / done |
| `respond` | subgraph_result | pending_action={approval_id, execution_summary} |
| `ignore` | — | final_verdict="ignored", stage="done", audit_log |

> ⚠️ **已知问题**：`aggregator` 把 stage 强制改成 "done"，使 `route_after_verdict` 的 `stage=="verify"` 分支永远走不到 → vuln_check→respond 链路死。已在审查中标记但当前版本未修复。

### 4.6 PoC 验证循环（vuln_hunter 子图，≤10轮）

```
START → generate_poc → linter_check → sandbox_exec → check_convergence
  ↑         │               │               │              │
  │         │               │               │         ┌────┴────┐
  │         │               └─(linter_fail)──┤    is_vuln?   iter≥10?
  │         │                               │         │          │
  └─────────┴───────────────────────────────┘     finalize   finalize
        (循环: 修复问题后重新生成)                    ↓          ↓
                                                   END       END

  generate_poc: LLM 生成 PoC；iteration_count++；写 memory.constraints
  linter_check: PoCLinter.check（语法/导入/危险调用，防 sys.modules 逃逸）
  sandbox_exec: SandboxExecutor.execute（Docker 隔离，network internal，stdout 找 "VULNERABLE"）
  check_convergence: is_vulnerable OR iteration>=10 → finalize；否则 generate_poc 重新生成
```
