## 一、项目定位

**SecAgent** 是一套基于大模型（LLM）的安全事件智能分析与自动响应平台，以 **「告警研判 + 漏洞扫描 + 响应处置 + 主机纳管 + AI 对话」** 五大能力构成安全运营闭环，当前正在向 **「Agent 主动监控 → Sigma 检测 → EDR 告警 → 智能研判 → 自动响应」** 的 EDR 全链路演进。

- **技术栈核心**：LangGraph 编排引擎 + FastAPI + React 18 + Go Agent + 7 个中间件
- **当前版本**：0.1.0（V13 审查基线 e3c84afa → HEAD 5a7c96ab）
- **质量状况**：ruff ✅ | mypy ❌ 11 errors（4 文件 unused type:ignore）| go vet ❌ 1 lostcancel | go test ✅ | pytest 本机不可收集（环境缺 jsonpatch）

## 二、已完成功能全景

### 1. 安全告警智能研判

| 功能 | 说明 |
|------|------|
| 告警接入 | Kafka（aiokafka）+ HTTP POST 双入口，带脱敏预处理；Kafka 入口含 DLQ 死信队列与稳定 event_id（P1-PRE-1） |
| 智能分流 | 入口 orchestrator：蜜罐规则优先命中 + LLM 分类兜底 |
| 多步推理链 | entry → 分流 → CTI分析 → 综合研判 → 汇聚 → 结论，每步带耗时/输入输出摘要 |
| IOC 提取+脱敏 | 自动提取 IP/域名/Hash/URL，7 条脱敏规则热加载（watchdog 监控） |
| 置信度评分 | VerdictResult（verdict + confidence + evidence + mitre_ttps），聚合后按置信度路由（≥0.8 响应 / 0.5–0.8 漏洞验证 / <0.5 归档） |
| GraphRAG 知识增强 | Milvus 向量检索 + Neo4j ATT&CK 图谱 + BGE-large-zh-v1.5 嵌入（1024 维）+ RRF 融合 |
| 威胁情报 | VirusTotal 并行查询 + AlienVault OTX |
| PoC 验证 | vuln_hunter 子图：LLM生成PoC → AST安全审查 → Docker沙箱隔离执行（≤10轮循环） |
| 推理链持久化 | ES 存储完整 trace，按 event_id 聚合查询 |
| 实时推送 | SSE 通道：事件流/单事件推理/指标流 |

### 2. EDR 告警接入与 Sigma 规则检测（★ 2026-07 新增，Phase 1-6）

| 功能 | 说明 |

### 4. 自动响应处置

| 功能 | 说明 |
|------|------|
| 预设剧本 | 10 个 YAML playbook（爆破/CVE利用/数据泄露/DDoS/DNS隧道/横向移动/恶意软件/钓鱼/勒索/未授权访问） |
| 剧本匹配 | trigger 规则优先（verdict + confidence_min + event_tags），未命中则 LLM 动态生成 |
| HITL 分级审批 | L1/L2 自动批准；L3 需 1 人；L4/L5 需 2 人 quorum（Redis Hash+Set+ZSet+Lua 原子实现） |
| 审批通知 | 企微/钉钉 webhook 推送审批卡片 |
| 超时兜底 | Celery 定时任务（L3=300s/L4=900s/L5=1800s） |
| 动作执行 | ActionDispatcher：notify / siem_tag / dns_block / simulator，幂等派发 + dry_run 默认开启 + 回滚支持 |
| Agent 端响应（★ Phase 4） | `src/agents/response_actions.py` + Go `internal/response/`：kill_process / quarantine_file（服务端签名下发，Agent 验签执行） |

## 四、核心流程

### 4.1 告警研判主图（main_graph）

```
entry → orchestrator(蜜罐+LLM分类) → route_decision
    ├─ low → ignore(归档)
    ├─ 带 vulnerability 标签 → vuln_check
    └─ high/medium → investigate
investigate / vuln_check → aggregator → route_after_verdict
    ├─ 确认真实漏洞(conf≥0.8 或 PoC 验证成功) → respond
    ├─ 存疑(0.5≤conf<0.8) → 回 vuln_check 二次验证
    └─ 低置信 → END(归档)
respond → END
```

- 子图挂载：investigation（CTI+GraphRAG 研判）、vuln_hunter（PoC 循环 ≤10 轮）、responder（playbook+HITL+执行）、vulnscan（独立 REST 驱动，与主图无边相连）
- 超时保护：investigate 120s / vuln_hunter 600s（recursion_limit=35）/ respond 300s，超时显式落 error 状态

### 4.2 Sigma 检测链路（★ 新增，Phase 1-6 现状）

```
Agent process 采集 ──WS──► monitor 上报 ──► ES
第三方 EDR ──► POST /alerts/ingest ──► edr_adapter.normalize ──┐
                                                            ├─► AlertStore (PG+ES) ──► 前端 AlertInboxPage
SigmaHQ 规则 ──► import_sigma_rules.py ──► rule_importer ──►  ├─► manifest JSON
内置 3 规则 ──► detector.load_builtin_rules (lifespan 加载) ──┘
POST /api/v1/detect ──► detector.run_rules(event) ──► build_alert(命中) ──► AlertStore
⚠️ 缺口：AlertStore 的告警尚未接入 run_pipeline 主图研判（V13 计划阶段 3）
```

### 4.3 漏洞扫描全流程

```
前端(表单/对话) → POST /vulnscan/tasks → vulnscan 子图:
  parse_intent → dispatch(建任务+签名广播, matcher/nuclei 双 lane)
  → collect(轮询+取消二次确认) → aggregate(去重/reconcile 分页全量)
  → llm_analysis(AI 过滤定级) → generate_report
        │  task_queue (Redis Stream) → TaskWorker 消费
        ▼
WS Gateway 签名指令(Ed25519) ──WS──► Go Agent
   matcher 规则匹配 / nuclei (port discovery + YAML 模板扫描)
   → scan_result 上报 → ES 存储 → SSE 实时推送 → 前端监控页
```

### 4.4 Agent 生命周期与命令

```
注册: enroll token(TTL) → POST /enroll → Ed25519 key exchange → agent_id+token
连接: WS 心跳(可配间隔) → 双向消息:
  ← scan_command / scan_cancel / rule_update / config_update
  ← agent_upgrade / nuclei_upgrade / nuclei_templates_update / response_action
  → heartbeat_ack / scan_result / resource_metrics / monitor_event
容错: 断线重连 + SQLite 离线缓存 + 跨 worker pub/sub 路由
终点: decommission (软下线) / purge (永久删除+断连 1011)
```

### 4.5 AI 对话 4 路路由

```
POST /api/v1/chat → LLM 意图分类 (异常→503+degraded, 低置信→chat 兜底)
  scan → ScanIntent → 确认卡片 → 执行扫描
  project → docs/*.md RAG（带来源）
  web → DuckDuckGo 多后端搜索 + RAG（带来源）
  chat → 直接 LLM 回答
持久化: PG JSONB 原子追加 + 自动标题(_spawn_title_task)
```
