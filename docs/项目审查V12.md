## 二、Standards 轴发现

### P1

**[S-P1-9]（新，本轴最严重）`_is_task_cancelled` fail-closed 语义错误：redis 抖动 = 健康任务被误杀 + agent 结果孤儿化 — ✅ FIXED（V12 阶段 1.1，`_confirm_cancellation` 二次确认 + audit，61 tests 全绿）**
- 位置：src/orchestration/subgraphs/vulnscan/nodes.py:1004-1044（定义），collect:466（每 5 秒轮询）、aggregate:562、llm_analysis:801、generate_report:1051、dispatch:181 均调用
- 证据：
  ```python
  except Exception as exc:
      get_logger(__name__).warning("nacos_cancellation_check_unavailable_treating_as_cancelled", ...)
      return True  # fail-closed: abort the node rather than run a cancelled task
  ```
- 问题：collect 在 30 分钟超时窗口内每 5 秒调一次（`while True:` → `_is_task_cancelled` → :466 `store.update_task(task_id, status="cancelled", ...)`）。任何瞬时 redis 故障（重启/部署/OOM/网络抖动）都会把**正在健康运行的任务**标记为 cancelled 并终止子图；agent 端扫描已通过 WS 下发且继续执行，结果写入 ES 后不会被 aggregate 归并/llm_analysis 处理——**结果孤儿化 + 运维看到虚假 "cancelled"**。
- **重要约束**：`tests/unit/orchestration/test_vulnscan_nodes.py:1115-1143` 的 `TestIsTaskCancelledFailClosed` 三个测试**明确锁定** fail-closed 行为（redis 连接错误 → 必须返回 True），这是 V11 批次 P2-1 的回归测试。**修法不能简单 fail-open**（会打破锁定测试）。
- 修法（兼容既有测试）：_is_task_cancelled 保持 fail-closed 语义，但调用方（collect:466 等）在 `update_task(status="cancelled")` 前**二次确认**（间隔 1s 重试一次，仍失败才落 cancelled，并写 audit `cancellation_check_degraded` + reason 标注 "unconfirmed"）；或 collect 轮询间隔从 5s 放宽到 15s 以缩小误杀窗口。二选一，都保留 fail-closed 回归测试。

## 附：为何两轴

一个变更可能通过一轴而失败于另一轴：

- 代码符合所有标准但实现错了东西 → **Standards 过，Spec 不过**。
- 代码完全按需求做但破坏项目约定 → **Spec 过，Standards 不过**。

分开报告可防一轴遮蔽另一轴。本文件保留两轴独立结论；后续修复计划（必须统一去重）在 [后续计划V12.md](后续计划V12.md)。
