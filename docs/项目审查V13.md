## 三、新发现问题（去重后全量）

### P0（3，安全红线）

**[G0-1]（Go，最严重）`response_action` 完全绕过 Ed25519 验签 → 明文通道中间人可注入杀进程/隔离文件命令**
- 位置：`agent/internal/crypto/verify.go:17-26`（`SensitiveTypes` 无 `"response_action"`）、`verify.go:49-51`（非敏感类型直接 `return nil`）、`agent/internal/comm/client.go:455-468`（response_action 分发路径）
- 证据（亲验）：服务端 `src/agents/signing.py:15-25` 的 `SENSITIVE_TYPES` **包含** response_action；`agent/internal/response/response.go:10-13` 文档声称「Agent rejects any response_action whose Ed25519 signature does not verify」——**实现与两端契约均背离**。默认 `ws://` 明文通道下，TCP 层中间人可注入任意 `response_action` 触发 `kill_process`（杀任意进程，仅拒绝 agent 自身 PID）与 `quarantine_file`（任意绝对路径 chmod 000 + rename）。`client_test.go` 无任何 response_action 用例。
- 修法：`SensitiveTypes` 加 `"response_action"` + 补 `TestHandleMessage_ResponseAction_RejectsBadSig`。**一行 + 一个测试。**

**[P0-1]（Python）Kafka 消费者重投死循环：唯一键冲突永不 commit → 消费者停摆**
- 位置：`src/preprocessing/consumer.py:85-94`（_emit 异常不 commit）+ `src/api/store.py:150-164`（`create_event` 裸 INSERT 无 ON CONFLICT）+ `src/orchestration/runner.py:22`（第一行 create_event）+ `src/common/db/pg.py:218`（`event_id VARCHAR(64) PRIMARY KEY`）
- 证据（亲验）：`_stable_event_id`（consumer.py:100-118）直接取 payload 的 `id/event_id/alert_id/uuid` 且跨源不加前缀。Kafka at-least-once 下，任何「处理完但 commit 前崩溃」的正常重投都会 INSERT 撞主键 → `_emit` 抛异常 → :88-94 不 commit → Kafka 无限重投同一条 → **每次必再撞主键 → 消费者永久卡死，该 offset 之后全部告警积压**。不同来源告警 id 撞车（如自增数字 id）同样触发。
